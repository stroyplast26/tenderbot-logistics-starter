# Видимость доставки Unisender GO (вебхук) — как включить

Зачем: у транзакционного API Unisender **нет статистики** (методы 404). Тихие спам-дропы
mail.ru (≈50% нашей очереди) локально не видны. Вебхук — единственный способ увидеть их
в реальном времени: Unisender шлёт нам события `delivered / soft_bounced / hard_bounced /
spam_block / spam / unsubscribed`. `spam_block` (и `delivery_status = err_spam_rejected /
err_blacklisted`) = именно то, что нам нужно поймать по mail.ru.

Всё живёт в одном файле: **`tb_webhook.py`**. Событий пишутся в `pool/delivery_events.jsonl`,
а реальные провалы доставки дублируются в `pool/events.jsonl` (kind=`bounce`) — так их
подхватывает **существующий** авто-сторож `_delivery_guard` в `tb_bot.py` и сам ставит паузу
при всплеске. Жалобы на спам и провалы приходят алертом в Telegram.

## Быстрый старт (один раз поставить cloudflared, дальше — один клик)

> Примечание 2026-07-29: на этом компьютере `cloudflared` не проходит до Cloudflare edge
> (`7844`/HTTP2 блокируется сетью), поэтому `START_WEBHOOK.bat` сейчас переключён на
> `python tb_webhook.py run-serveo`. Старый режим `python tb_webhook.py run` оставлен как запасной,
> если сеть для Cloudflare позже откроют.

1. Поставь cloudflared (бесплатно, без аккаунта):
   ```
   winget install --id Cloudflare.cloudflared
   ```
   (либо положи `cloudflared.exe` рядом с `tb_webhook.py`).

2. Запусти **`START_WEBHOOK.bat`** (или `python tb_webhook.py run`).
   Он сам: поднимет ловец → поднимет quick-туннель → зарегистрирует URL в Unisender.
   Окно оставь открытым. `Ctrl+C` — остановить (регистрация вебхука снимется).

3. Проверка: как только кампания пошлёт очередное письмо, событие упадёт в
   `pool/delivery_events.jsonl`. Через час-сутки смотри сводку:
   ```
   python tb_webhook.py report            # за всё время
   python tb_webhook.py report --days 1   # за сутки
   ```
   Внизу отчёта — прямой ответ: `mail.ru: доставлено X/Y (Z%), спам-блоков N`.

> ⚠️ Quick-туннель даёт **новый URL при каждом запуске**. `run` регистрирует его автоматически,
> так что просто перезапускай `START_WEBHOOK.bat` — он сам перерегистрирует. Для постоянного
> URL нужен свой домен/named-tunnel (позже).

## Ручной режим (свой туннель: ngrok или домен)

```
python tb_webhook.py serve                 # окно 1: ловец на :8765
ngrok http 8765                            # окно 2: свой туннель
python tb_webhook.py register https://<url-из-туннеля>   # зарегистрировать
python tb_webhook.py list                  # проверить регистрацию
python tb_webhook.py unregister https://<url>            # снять
```

## Что означают статусы

| статус         | смысл                                                        |
|----------------|-------------------------------------------------------------|
| `sent`         | Unisender принял и отдал MTA (ещё не доставлено)             |
| `delivered`    | сервер получателя принял письмо (в инбокс ИЛИ в спам-папку)  |
| `soft_bounced` | временный сбой (переполнен ящик и т.п.) — не фатально        |
| `hard_bounced` | постоянный отказ (нет ящика / заблокирован) → в `bounce`     |
| `spam_block`   | **сервер получателя отбил как спам** (главный сигнал mail.ru) → в `bounce` |
| `spam`         | получатель нажал «это спам» (жалоба, бьёт репутацию домена)  |

Ограничение честно: `delivered` = «сервер принял», но mail.ru может принять и молча положить
в спам-папку. Различить инбокс/спам-папку точно можно только open-трекингом (сейчас выключен —
нет tracking-домена в отправке) или сид-тестом на свой mail.ru-ящик. Но `spam_block`/`hard_bounced`
по mail.ru мы теперь видим полностью — это и есть громкий отказ, которого раньше не было видно.

## Безопасность

Ловец проверяет подпись Unisender (md5 тела с подстановкой api_key) — поддельные `bounce`-события
снаружи инжектировать нельзя (не прошедшие подпись POST-ы молча дропаются, но всегда отвечаем 200,
чтобы Unisender не пометил вебхук неактивным). API-ключ берётся из `.env` (`UNISENDER_GO_API_KEY`).
