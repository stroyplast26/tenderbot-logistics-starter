# TaskBot

Отдельный Telegram-бот для управления задачами Bitrix24. Он не использует и не меняет токен, вебхук или циклы рассылочного TenderBot.

## Статус после восстановления

TaskBot — опциональный live-sidecar, а не entry point Market & Demand OS v7.
В recovery-baseline он не запускается, не добавляется в HKCU Run и не
подключается к Telegram, Bitrix или OpenRouter. SETUP_TASKBOT_AUTOSTART.bat
по умолчанию завершится с кодом 77.

Для будущего явно разрешённого запуска:

1. Восстановите общую CPython 3.11 среду по корневому README.
2. Скопируйте taskbot/.env.example в taskbot/.env.
3. Заполните TASKBOT_TELEGRAM_TOKEN, BITRIX_TASKS_WEBHOOK и
   OPENROUTER_API_KEY. Не переносите абсолютный путь к настройкам из старого
   Windows-профиля.
4. Установите корневой `requirements-dev-win-py311.lock.txt` и выполните
   локальные тесты до подключения:

       .\python_runtime.bat -m pytest -q -p no:cacheprovider taskbot\tests

5. Только после отдельного решения владельца запустите START_TASKBOT.bat.

## Что работает в первом контуре

- `/today` — открытые задачи текущего пользователя из Bitrix24;
- обычный текст или голосовое — AI выделяет задачу, срок и приоритет, затем показывает явное «Создать»;
- `/task Текст` — явный вариант личной задачи;
- `/to @алиас Текст` — постановка задачи партнёру или сотруднику (только роли `owner` и `partner`);
- защита от дублей Telegram update и от повторного подтверждения;
- в 09:00 — утренний фокус и список открытых задач, в 18:00 — короткое закрытие дня; повторов после рестарта нет;
- рабочая карточка задачи: «в работу», следующий шаг, голосовое/текстовое обновление, блокер, история и завершение только после результата;
- постановщик видит принятие, прогресс и блокер по поручению; бот отдельно напоминает о непринятом поручении и первом обновлении;
- локальная SQLite хранит черновики, идемпотентность и рабочий контекст (следующий шаг, прогресс, блокер); источником истины по самой задаче и её завершению остаётся Bitrix24.

## Подключение людей

1. Скопируйте `users.example.json` в `users.json`.
2. Каждый человек пишет новому боту `/start`; бот показывает его Telegram ID, пока привязка не добавлена.
3. В `users.json` укажите Telegram ID, Bitrix24 user ID, короткий алиас и роль (`owner`, `partner`, `employee`). Файл намеренно не попадает в Git.
4. Явный запуск после approval: дважды нажмите `START_TASKBOT.bat` или выполните
   `python_runtime.bat -m taskbot.app`.
5. Автозапуск не является частью recovery. Его установщик остаётся заблокированным,
   пока владелец отдельно не разрешит live-sidecar.

## Голосовые и AI

TaskBot использует OpenRouter: `openai/whisper-1` для голоса и отдельную текстовую модель для извлечения названия, срока, приоритета и исполнителя. Файл голосового скачивается только во временную папку и удаляется до показа карточки. Для переносимого развёртывания добавьте `OPENROUTER_API_KEY` в `taskbot/.env`. `OPENROUTER_SETTINGS_PATH` оставлен только как опциональный fallback и не должен ссылаться на профиль другого пользователя.

## Безопасность

- Шаблон `taskbot/.env.example` не содержит секретов; реальные значения находятся
  только в игнорируемом `taskbot/.env`.
- Для существующего TenderBot остаются его старые переменные и вебхук.
- В чатах не выводятся токены и вебхуки.
- `taskbot.supervisor` перезапускает TaskBot после аварийного завершения; состояние напоминаний хранится в SQLite.
