# TenderBot — автопоиск тендеров с остеклением (для АлюмКомплект)

Состав сохранённой версии и известные ограничения проверки описаны в
[снимке исходников от 7 сентября 2026 года](docs/SOURCE_SNAPSHOT_2026_09_07.md).

Добавлено [локальное рабочее место менеджера по строительным объектам](docs/RADAR_MANAGER_WORKBENCH.md):
досье Radar, назначение задачи, результат общения и следующий срок.
Демонстрация и импорт согласованных публичных сведений описаны в инструкции;
подключение живых источников и CRM ещё требует отдельной проверки.

## Текущее состояние после восстановления Windows

Действующая runtime-authority остаётся привязана к Market & Demand OS v7.1 RC1 в
docs/market_demand_os_v7 и lead_factory/mdos_v7. Отдельный successor-кандидат
7.2.0-rc.2 находится в docs/market_demand_os_v7_2: он добавляет операторский и
телефонный контур, точный release pin и локальные доказательства, но не заменяет
authority 7.1 и не даёт live-разрешения. Единственное отдельно подготовленное
исключение пересмотрено после проверки живого Bitrix: штатная Bitrix24 Mail уже
принимает письма и остаётся единственным CRM writer для этого ящика. Старый
Mail.ru → Bitrix V4 writer отозван и не должен активироваться. Новый контур по
`docs/LIVE_CONNECTIONS_OBSERVER_RUNBOOK.md` только читает IMAP и
`crm.activity`, сверяет нативную проекцию и пишет локальный ledger/review; он не
создаёт Lead, Todo, Timeline и не назначает оператора. До сборки, проверки и
отдельного включения защищённого observer-релиза фоновая задача остаётся
выключенной. Исходящие письма/рассылки, MANGO, TenderPlan и любые другие внешние
действия по умолчанию выключены. SETUP_*.bat не нужно запускать для recovery.

Корневые tb_*.py и старые batch-файлы сохранены как legacy-контур. Они не
являются командой запуска v7 и не должны использоваться для боевой отправки
без отдельного решения владельца и прохождения contract gates.

## Восстановление локальной среды

Проект рассчитан на CPython 3.11.9 x64. Скопированную с другого Windows-профиля
.venv нельзя чинить заменой путей: её нужно сохранить как backup и создать заново.
Канонический bootstrap сам создаёт repo-local `.venv`, ставит закреплённые
runtime/development dependencies и затем проверяет точный interpreter/toolchain.

    winget install --exact --id Python.Python.3.11 --version 3.11.9 --source winget --scope user --accept-package-agreements --accept-source-agreements --disable-interactivity
    Rename-Item .venv .venv.pre-reinstall
    powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap_python_runtime.ps1
    powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap_python_runtime.ps1 -CheckOnly

Для нового безопасного source/Gold flow используйте только fail-closed launcher;
он повторяет `-CheckOnly` и не допускает fallback Python:

    .\scripts\run_safe_lead_flow.ps1 source plan

Ограничения, metered provider reads, cap-one и текущий STOP перед Gold
signer/promotion описаны в
[`docs/SAFE_LEAD_FLOW_LAUNCH_RUNBOOK.md`](docs/SAFE_LEAD_FLOW_LAUNCH_RUNBOOK.md).

Отдельные lock-файлы `requirements-report-win-py311.lock.txt` и
`requirements-ocr-win-py311.lock.txt` добавляют Pillow и optional OCR wrapper.
Для OCR также требуется системный Tesseract с языками rus/eng.

Полный offline regression и lint:

    .\python_runtime.bat -m pytest -q -p no:cacheprovider
    .\.venv\Scripts\ruff.exe check .

Первичная безопасная проверка сохранённого stage-состояния:

    .\python_runtime.bat -m lead_factory.cli status
    .\python_runtime.bat -m lead_factory.cli work-queue

Эти команды не включают внешние сервисы и остаются общей локальной диагностикой,
но не являются точкой входа нового source/Gold flow. Не запускайте init или
явную миграцию канонической schema v16 в рамках recovery-baseline. Общий legacy
`python_runtime.bat` может искать CPython через `TENDERBOT_PYTHON`, стандартную
user-installation, py launcher или PATH; для нового flow такой fallback запрещён,
и его нельзя использовать вместо `run_safe_lead_flow.ps1`.

Для локальных секретов скопируйте .env.example в .env и заполните только
явно разрешённые интеграции. Пустые секреты подходят для offline-тестов.

## Git и GitNexus

Публичный репозиторий актуальных исходников:
[stroyplast26/tenderbot-logistics-starter](https://github.com/stroyplast26/tenderbot-logistics-starter).
По решению владельца прежняя логистическая копия заменена снимком TenderBot
от 7 сентября 2026 года. Публичная ветка `main` начинается с нового корневого
коммита; локальная история восстановления и резервные копии не публикуются.

Проект индексируется GitNexus 1.6.10. `.gitnexusrc` закрепляет имя `TenderBot`,
ветку `main`, PDG-анализ и лимит 2 МБ, чтобы в граф попадали крупные модули v7.
Сам индекс находится в игнорируемой `.gitnexus/`; отслеживаются только контекст
и настройки. Восстановление инструмента на новой машине:

    winget install --exact --id OpenJS.NodeJS.22 --scope user
    npm install --global gitnexus@1.6.10
    gitnexus setup -c codex
    gitnexus analyze

Проверка индекса и обновление после изменений:

    node .gitnexus\run.cjs status
    node .gitnexus\run.cjs analyze

## Legacy TenderBot: как это работало

Программа раз в сутки сама находит **уже завершённые** тендеры в Москве и МО, где есть
остекление/светопрозрачные конструкции, оценивает их через ИИ и присылает вам на почту
готовые лиды с контактами победителя и черновиком письма.

### Как это работает (простыми словами)

Основной источник — **реестр контрактов ЕИС (zakupki.gov.ru), 44-ФЗ**: там у каждого контракта
**виден победитель** (ИНН + название), данные свежие, бесплатно и без лимитов. (Настройка `source`.)

1. **Ищет** свежие заключённые контракты 44-ФЗ в Москве и МО по «неводам»:
   тип объекта (школа, ЖК, ФОК, бизнес-центр…) + прямое остекление (витраж, фасад…).
   Регион определяется по номеру контракта (цифры 2–3 = код региона: 77/50).
2. **Берёт победителя** из карточки контракта: название, ИНН, КПП, адрес, **телефон, email**, цену.
3. **Оценивает ИИ** (Claude через OpenRouter): наш ли это профиль, балл 1–5, рекомендация,
   черновик письма генподрядчику-победителю.
   - **Точная оценка по смете (v2):** для перспективных лидов программа находит смету/ВОР/ЛСР в
     документах закупки, скачивает (xlsx/docx/pdf), вынимает строки про остекление (м² витражей,
     шт. окон) и отдаёт ИИ → объём становится конкретным. Такие лиды помечены «📋 оценка по смете».
     Управляется в `config.toml`: `enrich_smeta`, `enrich_min_ball`.
   - **Документы в письме:** к лиду прикладываются смета/ВОР и ТЗ (целиком), а из проекта-PDF
     **вырезаются только листы по нашей части + общий фасад** (отдельный небольшой PDF
     «листы (остекление+фасад)»). Скан/DWG/слишком большой проект → остаётся ссылкой. Лимиты и
     включение — в `config.toml`: `attach_drawings`, `drawing_max_pages`, `attach_max_total_mb`.
4. **Проверяет победителя** по ИНН через DaMIA: РНП (реестр недобросовестных), СМП
   (не малый бизнес → «горячий лид», ч.5 ст.30) и **досье** (сколько контрактов и на какую сумму
   → пометка «💪 активный подрядчик», такие лиды идут выше). Настройки: `check_winner_activity`,
   `winner_active_min_contracts`, `winner_active_min_sum`.
5. **Шлёт письмо** со списком лидов (вверху сводка: горячих/балл≥4/активных/со сметой; лучшие — первыми)
   + сохраняет HTML-отчёт в папку `reports`. Если прогон упал — присылает **письмо-тревогу** (`alert_on_failure`).
6. **Не повторяется**: уже отправленные контракты запоминаются (папка `state`).

> Телефон и email победителя берутся прямо из карточки контракта ЕИС (раздел «Информация о
> поставщиках») и попадают в лид. Где их нет — остаётся название + ИНН + ссылка на карточку.
>
> Старый источник DaMIA (`source = "damia"`) ищет шире, но по свежим закупкам победитель там
> обычно скрыт (это в основном 223-ФЗ). Поэтому по умолчанию используется ЕИС.

## Файлы

- `config.toml` — **настройки** (ключевые слова, регион, ОКПД, порог балла, лимиты). Можно править.
- `.env` — **секреты** (ключи и пароли). Никому не показывать, в git не попадает.
- `tb_main.py` — главная программа. Остальные `tb_*.py` — её части.
- `reports/` — HTML-отчёты по датам. `logs/` — журналы. `state/` — память (что уже отправлено).

## Legacy-запуск (только после отдельного разрешения)

Следующие команды описывают старый контур. Они не входят в recovery и могут
обращаться к сети или менять локальное состояние. Установщики автозапуска
дополнительно заблокированы до явного одноразового opt-in через переменную окружения.

- **`ТЕСТ_показать_лиды.bat`** — пробный прогон: найдёт лиды и покажет на экране. **Ничего не шлёт.**
- **`ПОСЕВ_отметить_старые.bat`** — запустить **один раз** перед первым боевым запуском: пометит
  все текущие завершённые тендеры как «уже виденные», чтобы не прислать сразу весь архив.
- **`run.bat`** — боевой прогон (ищет новые, шлёт письмо). Его же запускает планировщик по расписанию.

Из командной строки то же самое:
```
run.bat --test       тест (печать, без отправки)
run.bat --seed       посев
run.bat              боевой прогон
run.bat --days 60    переопределить окно поиска
run.bat --no-email   боевой прогон без отправки (только отчёт)
```

## Исторический порядок первого запуска legacy-контура

1. `ТЕСТ_показать_лиды.bat` — убедиться, что лиды находятся и выглядят адекватно.
2. (после настройки почты) `ПОСЕВ_отметить_старые.bat` — один раз.
3. Дальше планировщик сам запускает `run.bat` каждый день.

## Настройки в config.toml (главное)

- `q_object` / `q_glazing` — ключевые слова (тип объекта / прямое остекление).
- `q_object_broad` — мега-широкие слова (строительство/реконструкция/капремонт). По умолчанию пусто,
  т.к. дают тысячи результатов и жгут квоту DaMIA. Включать при большом тарифе.
- `regions` — `77,50` (Москва + область).
- `recency_days` — **брать контракты, заключённые не старше N дней** (по умолчанию 90 = 3 месяца).
  Отсекает старые контракты (они всплывают из-за недавнего «обновления»).
- `min_price` — **минимальная цена контракта** (по умолчанию 5 000 000 ₽; дешевле — не показываем).
- `min_ball` — порог балла ИИ для отправки (по умолчанию 2).
- `skip_product_words` — **стоп-слова по названию**: клининг, **ПВХ/пластик** (не наш профиль),
  **проектирование/ПСД/экспертиза/осмотр/надзор** (закупки без работ) — отсеиваются сразу.
- `attach_keywords` / `attach_max_file_mb` / `attach_max_total_mb` — какие файлы прикладывать
  (сметы/ВОР) и лимиты вложений.

## Сколько стоит

- **ЕИС (основной источник)**: бесплатно, без лимитов. Прогон идёт несколько минут
  (`eis_max_pages` регулирует охват/длительность).
- **DaMIA**: используется только для проверки победителя по ИНН (РНП + СМП) — это ~1–2 запроса
  на лид. На тарифе 1000/метод хватает надолго. Можно отключить: `check_rnp=false`, `check_eruz=false`.
- **OpenRouter (ИИ)**: оценка одного лида — доли цента. Лимит обработки на запуск — `max_per_run`.

## Если что-то не так

- Смотрите свежий файл в `logs/`.
- «Квота DaMIA исчерпана» — пополните тариф или сузьте поиск (меньше слов, выше `min_price`).
- Письмо не уходит — проверьте SMTP-поля в `.env` (для Яндекс/Mail нужен **пароль приложения**).
