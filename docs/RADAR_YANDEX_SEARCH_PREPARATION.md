## Что работает в этой поставке

`lead_factory/radar_yandex_search.py` выполняет три локальные операции:

1. `plan` готовит 20 начальных запросов по пяти регионам, проверяет общий
   предложенный предел операций и арифметику бюджета.
2. `preview` разбирает **переданный локальный** ответ синхронного API. Сохраняет
   исходный порядок, заявленные query/page, rank, URL, SHA-256 точных байтов и заявленное время
   получения. Отдельный индекс ссылок объединяет одинаковые URL и сохраняет все
   появления. Разные страницы одного домена остаются разными ссылками.
3. `prepare-import` связывает выбранный результат с **отдельной ручной
   транскрипцией проверенной страницы** и декларацией проверившего оператора.
   Возвращает `import_json` и `discovery_receipt`. Существующий `import-radar`
   затем проверяет утверждённый паспорт и записывает досье. Подготовка сама базу
   не открывает и паспорт не создаёт.

Эти три команды печатают JSON в stdout и не изменяют входные файлы. Ошибка CLI
даёт код 2 и короткую классификацию без содержимого ответа или локального пути.
Вызов `fetch_yandex_search` запрещён существующим fixed RC1 ещё до любой работы
с секретом или сетью. Этот старый entry point остаётся закрытым; новый runner
находится в `lead_factory/radar_yandex_transport.py` и тоже сначала вызывает
существующий fixed RC1, до открытия журнала, чтения ключа или HTTP.

**Проверка арифметики плана не является резервированием денег.** Новый отдельный
`radar_yandex_journal.py` сохраняет резервы и состояния в SQLite. Это локальная
оценка максимального расхода, не разрешение, платёж и не банковский счётчик.
Нет скрытого включения через `env`, fixture, новый паспорт или поле бюджета.

## Предложение разового пилота — не разрешение

| Параметр | Предложение |
| --- | --- |
| Источник | Только обычный синхронный Yandex Search API v2 |
| Регионы | Краснодарский и Ставропольский края, Ростовская область, Татарстан, Свердловская область |
| Начальный поиск | 4 тематических запроса на регион, всего 20 |
| Темы | Гостиницы/общественные здания, коммерческие здания, производство, закупки окон/дверей/фасадов |
| Дальнейшие запросы | До 80 арифметических слотов; текущий journal разрешает только свои 20 точных запросов, расширение плана не реализовано |
| Общий предел | 100 HTTP-попыток, включая повторные и неясные исходы |
| Предлагаемая скорость | 1 запрос/с; автоматических повторов нет |
| Предлагаемый потолок | 60 ₽, RUB, все суммы в целых копейках |
| Плановый резерв | 49 копеек на попытку; 100 × 49 = 4900 копеек |
| Цель | 20–30 **исследованных** объектов; выход не гарантирован |

Текущий дневной тариф обычного sync — 488 ₽ за 1000 запросов с НДС:
100 запросов = 48,80 ₽. Резерв 49 копеек округлён вверх; его нужно пересмотреть
при изменении тарифа. Сумма 60 ₽ не разрешает превысить 100 попыток. Инфоконтексты,
генеративные ответы, отложенный поиск, Maps и геокодирование в scope не входят.
[Тариф](https://aistudio.yandex.ru/ru/docs/search-api/pricing).
Облачный бюджет лишь уведомляет и не останавливает потребление.
[Бюджет Cloud](https://yandex.cloud/ru/docs/billing/concepts/budget).

## API-контракт transport

`POST https://searchapi.api.cloud.yandex.net/v2/web/search`, `Authorization: Api-Key`.
Сервисному аккаунту требуется `search-api.webSearch.user`, API-ключу —
scope `yc.search-api.execute`. `folderId` задаётся явно и связывается с разрешением.
Описанный ниже исторический low-level owner-pilot runner получал ключ из
`YANDEX_SEARCH_API_KEY`; это отдельный неподдерживаемый для первого safe flow путь,
у которого сейчас нет activation. Канонический `run_safe_lead_flow.ps1` удаляет
ambient key и получает секрет только через фиксированный DPAPI broker после
authority, durable reservation и cache miss. Ключ нельзя передавать в чат, PR,
аргументы команды или логи.
[Аутентификация](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/authentication),
[синхронный поиск](https://aistudio.yandex.ru/ru/docs/search-api/operations/web-search-sync).

`SearchRequest.body(folder_id)` строит JSON по REST reference: `SEARCH_TYPE_RU`,
`FIX_TYPO_MODE_OFF`, `GROUP_MODE_FLAT`, 10 групп × 1 документ, 2 passages,
`LOCALIZATION_RU`, `FORMAT_XML`. Страницы 0–24 задаются явно. Query ограничен
400 символами и 40 словами. Строка `region=225` влияет на ранжирование и
не доказывает регион объекта. Регион в тексте запроса — направление исследования.
Фильтр периода и `metadata` исключены: сейчас разные страницы документации
расходятся в именах `period/PERIOD_*` и `resultsWithin/WITHIN_*`.
[REST reference](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/WebSearch/search),
[лимиты](https://aistudio.yandex.ru/ru/docs/search-api/concepts/limits).

Transport использует проверяемый TLS через стандартный `HTTPSConnection`:
фиксированный host/path, без redirect, поиска proxy в окружении и retry.
Socket timeout — 10 секунд; после connect watchdog ограничивает отправку,
заголовки и чтение 30 секундами, прерывая точный TLS socket через shutdown;
системный DNS не имеет гарантированного общего срока через этот Python API.
Streaming cap — 1 MiB; неуспешный HTTP, сжатый/не-JSON ответ или несовпадающий
Content-Length считаются неопределённой попыткой. Тело HTTP-ошибки не читается.
Отдельный `x-client-request-id` записан до отправки, в journal попадают только
безопасные `x-request-id`/`x-server-trace-id`. `x-data-logging-enabled=false`.
[Заголовки](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/support-headers).

## Семантика и права

Ответ — JSON `rawData`, Base64 UTF-8 XML. Parser ограничивает JSON 1 MiB,
XML 512 KiB, 2000 элементов, глубину 16 и 10 документов. Он отклоняет DTD,
entities, processing instructions, duplicate JSON fields, неизвестную структуру,
ошибки провайдера и неоднозначные поля. XML error 15 без результатов означает
пустую выдачу. Отсутствующий или опасный URL исключается из индекса ссылок,
но его исходное место остаётся в `search_pages` с причиной отказа.

`received_at_utc` — **заявленная** дата получения переданного файла;
`capture_verified=false`. Parser не утверждает, что он делал fetch.
Query/page задаются оператором; когда XML содержит request echo, противоречие
отклоняется. Без echo связь с запросом остаётся заявленной. Rank вычисляется
из позиции документа в XML и заявленной страницы, а не удостоверяет live capture.
`provider_modtime` — необязательное поле поисковика, не дата строительного факта.
Заголовки и сниппеты не устанавливают адрес, стадию, участников, ИНН, закупщика,
количество конструкций или потребность в алюминии. Очередь ограничена 30 ссылками,
с явным количеством оставшихся ссылок; это не 30 объектов или лидов.

Исходная выдача в `search_pages` сохраняет порядок каждого запроса, включая
повторяющиеся URL. `candidates` — отдельный индекс ссылок для исследования,
не переупорядоченная SERP. Условия Search API §3.2 запрещают менять порядок
результатов; текущая редакция действует с 07.09.2026.
[Условия](https://yandex.ru/legal/cloud_terms_search_api/ru/).

В проверенных условиях не найдено явного срока локального хранения. Это не
доказательство права на бессрочный архив выдачи. Эта версия не сохраняет raw
response или snippets в immutable Radar vault и не присваивает им BUSINESS_PUBLIC.
Предоставленный файл может быть реальным или синтетическим: оба вида обрабатываются
как supplied/unverified, реальное не переименовывается в fixture.

`prepare-import` требует выбранный rank, точное совпадение исходного URL, явный reviewer,
время и декларации проверки источника и прав бессрочного хранения именно
публичной транскрипции. Правила manual import запрещают query/fragment в source URL:
такие результаты можно исследовать, но нельзя молча удалить query и импортировать
другую страницу. Нужен отдельный подтверждённый источник и его собственное
происхождение. Даты фактов и идентичность объекта задаются оператором.

`discovery_receipt` — локальная декларация, **не** API receipt или лицензия.
`passport_verified=false` до проверки actual importer. Сохраните receipt рядом
с транскрипцией по принятому сроку хранения; этот sidecar пока не отображается
как проверенная связь в UI Radar. Само досье сохраняет ссылку/даты/evidence ручной
транскрипции по существующему протоколу. Никаких CRM/outbox/сообщений в подготовке.

## Запуск локальной подготовки

Из корня worktree, с рабочим Python (`python` ниже — доступный Python 3.11):

```powershell
python -B -X utf8 -m lead_factory.radar_yandex_search plan
python -B -X utf8 -m lead_factory.radar_yandex_search preview --file LOCAL_RESPONSE.json --query "Краснодарский край строительство гостиницы 2026" --region "Краснодарский край" --received-at "2026-09-07T12:00:00Z"
python -B -X utf8 -m lead_factory.radar_yandex_search prepare-import --file LOCAL_RESPONSE.json --query "Краснодарский край строительство гостиницы 2026" --region "Краснодарский край" --received-at "2026-09-07T12:00:00Z" --rank 1 --public-record REVIEWED_PUBLIC_RECORD.json --passport EXISTING_APPROVED_PASSPORT --reviewer manager-1 --reviewed-at "2026-09-07T13:00:00Z" --source-checked --rights-checked
```

Имена файлов — placeholders для уже имеющихся локальных материалов, не команда
скачивания. Для нескольких ответов Python API `build_review_queue(pages)` принимает
до 100 разобранных страниц. Повтор точного capture ничего не добавляет; разные
captures одного operation key требуют отдельного исследования, не тихого replay.

Из `prepare-import` в файл для `import-radar` передаётся только `import_json`,
не весь envelope. Структура транскрипции описана в
[RADAR_WORKBENCH_MANUAL_IMPORT.md](RADAR_WORKBENCH_MANUAL_IMPORT.md).
Существующая команда `import-radar --workspace-db ... --actor ... --passport ...
--file ...` проверит действующий approved MANUAL_IMPORT BUSINESS_PUBLIC паспорт.
После импорта объект доступен в [рабочем месте менеджера](RADAR_MANAGER_WORKBENCH.md).
Отчёт менеджера о запросе расчёта по-прежнему не является подтверждённой продажей.

## Постоянный журнал и команды оператора

Journal — отдельный явно выбранный файл. `init` создаёт его эксклюзивно; остальные
команды открывают только существующий файл и требуют сохранённый SHA-256 policy.
Исчезнувший файл не восстанавливается автоматически. Policy связывает endpoint,
digest folder, точные query/page, сроки, лимиты и срок доступа к ответам.
Изменение policy после создания, продление и сброс счётчиков не предусмотрены.
Журнал защищает от обычного рестарта и конкурирующих процессов, но не доказывает
отсутствие отката копии файла или второго журнала. Successor authority должна
привязать один канонический journal; сам `init` не даёт права расходовать деньги.

`reserve` коммитит попытку и полный резерв; `mark_dispatch_intent` отдельным
коммитом фиксирует единственную возможную отправку. Незавершённая или UNCERTAIN
попытка блокирует продолжение до отдельного расследования. Автовосстановления
отправкой нет. Завершённый, в том числе пустой, ответ возвращается локально.
Неуспех, остановка процесса и очистка ответа не возвращают лимит.

**STOP запрещает новые dispatch intents.** Уже закоммиченный intent означает одну
возможную in-flight попытку: она может отправиться или закончиться после STOP.
STOP не обещает отмены этой попытки. Точный завершённый и ещё не просроченный
ответ можно читать локально после STOP; другой request key не создаёт новый
intent. Expiry проверяется при выдаче intent; откат часов отвергается. Между
intents — не менее одной секунды, без автоповтора.

Примеры используют placeholders, не реальные account IDs или ключи:

```powershell
python -B -X utf8 -m lead_factory.radar_yandex_transport init --journal tmp/yandex-pilot.sqlite --pilot-id pilot-1 --folder-id FOLDER_ID --expires-at "2026-09-08T18:00:00Z"
python -B -X utf8 -m lead_factory.radar_yandex_transport status --journal tmp/yandex-pilot.sqlite --policy-sha256 POLICY_SHA256
python -B -X utf8 -m lead_factory.radar_yandex_transport stop --journal tmp/yandex-pilot.sqlite --policy-sha256 POLICY_SHA256
python -B -X utf8 -m lead_factory.radar_yandex_transport replay --journal tmp/yandex-pilot.sqlite --policy-sha256 POLICY_SHA256 --request-index 0
python -B -X utf8 -m lead_factory.radar_yandex_transport purge --journal tmp/yandex-pilot.sqlite --policy-sha256 POLICY_SHA256
```

`init` печатает policy digest; его сохраняют вместе с точным путём journal.
`run` имеет те же параметры выбора journal/request и явный `--folder-id`, но
сейчас всегда завершается отказом fixed RC1. В CLI нет флага включения live.

Временный raw response хранится только здесь, вне immutable Radar vault.
`retention_hours` для operational exact job обязан быть равен ровно 24 часам;
любое другое значение отклоняется и требует нового решения до live. По истечении
доступ запрещён; `purge` удаляет payload и correlation
headers, сохраняя hash/расход/состояние. Команду очистки должен запускать оператор:
фонового таймера нет. SQLite использует DELETE journal и secure_delete; это не
гарантия удаления резервных копий или восстановления данных средствами ОС.
Replay сохраняет `capture_verified=false`: запись ответа не подтверждает факт
строительства, покупателя, стадию объекта или юридические права на хранение.
