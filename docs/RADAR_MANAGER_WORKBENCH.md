# Рабочее место по строительным объектам

Первый доступный через браузер сценарий: объект Radar → досье → исполнитель и
срок → краткий результат менеджера → следующий шаг. Это локальная версия для
одного доверенного оператора на компьютере. Она использует существующие таблицы
Radar, events, interactions и human_tasks; отдельного реестра объектов нет.

## Запуск

Из корня проекта с подготовленным Python 3.11:

```powershell
.\python_runtime.bat -B -m lead_factory.cli serve-radar --workspace-db state/radar-manager-demo.sqlite3 --actor manager-1 --demo
```

Откройте `http://127.0.0.1:8766`. `--demo` создаёт только новую базу с тремя явно
вымышленными объектами; существующий файл не заменяет. Для повторного открытия
этой же базы уберите `--demo`. Баннер демонстрации остаётся после перезапуска:
сервер проверяет сохранённый маркер. При повреждении маркера запуск отклоняется.

```powershell
.\python_runtime.bat -B -m lead_factory.cli serve-radar --workspace-db state/radar-manager-demo.sqlite3 --actor manager-1
```

Завершение — Ctrl+C в терминале сервера. Записи остаются в выбранной базе.
Не используйте рабочую защищённую runtime-базу для демонстрации. Для реальных
данных выберите отдельную исследовательскую базу. Параметр `--workspace-db`
обязателен и не наследует глобальный `--db`. Существующие схемы не мигрируются;
рабочее место требует Radar schema 15 или новее.

Оператор задаётся при запуске: например `manager-1`, `owner` или внутренний ID.
Русское отображаемое имя пока не поддерживается. Результат может записать только
текущий исполнитель задачи. Это локальная атрибуция, а не система входа сотрудников:
пользователь компьютера, запускающий сервер, может выбрать ID. Для нескольких
менеджеров нужны отдельная авторизация, роли и CRM-проекция. Не публикуйте этот
сервер в интернете и не подключайте его через внешний reverse proxy.

## Работа менеджера

1. Выбрать объект. Проверить источник, дату, стадию, участников и предполагаемую
   потребность. Устаревшие/заменённые версии сохраняются с соответствующей пометкой.
2. Назначить исполнителя и будущий срок. Очередь позволяет найти свои задачи,
   просрочки, объекты без исполнителя и вопросы к сведениям. Фильтры и поиск
   действуют на загруженной странице; страницы содержат до 100 объектов.
3. После самостоятельной проверки или общения сохранить краткий итог.
   Программа сама выбирает допустимые следующие действия и требует срок.
4. Вернуться к истории и проверить договорённости. Конкурирующее изменение
   отклоняется по версии; одинаковая команда не создаёт второй результат.

| Результат | Следующее действие |
| --- | --- |
| Недозвон / договорились перезвонить | Перезвонить, со сроком |
| Нужны сведения | Собрать сведения или уточнить потребность, со сроком |
| Получен запрос расчёта | Подготовить расчёт и КП, со сроком |
| Подготовлено КП | Обсудить предложение, со сроком |
| Исследование завершено / объект не подходит | Завершить задачу |
| Попросили не связываться | Завершить и заблокировать дальнейшую работу по объекту |

Отказ от контакта действует только в этом рабочем месте для этого объекта.
Он пока не синхронизируется с общей блокировкой адресата в каналах связи.
Завершённые задачи сейчас нельзя повторно открыть через этот интерфейс.

Запрос расчёта и КП — сведения со слов менеджера. Они не создают подтверждённую
сделку, входящий ответ, документ, расчёт, отправку или CRM-стадию. Краткая заметка
остаётся в локальном журнале с автором; не вставляйте стенограммы, пароли или
лишние персональные сведения. Загружать файлы в браузере эта версия не умеет.

## Реальные сведения

Добавлен [импорт официального CSV разрешений Мегиона](RADAR_MEGION_PUBLIC_PERMITS.md):
очищенные сведения юрлиц, версии источника и проверяемое происхождение в досье.
Получение файла пока выполняется отдельно; регулярный API-сбор не включён.

Подготовлен [импорт публичных сведений](RADAR_WORKBENCH_MANUAL_IMPORT.md) из явно
выбранного JSON-файла в уже согласованный паспорт источника:

```powershell
.\python_runtime.bat -B -m lead_factory.cli import-radar --workspace-db state/radar-research.sqlite3 --actor owner --passport <approved-passport-id> --file <public-object.json>
```

Паспорт не создаётся и не утверждается этой командой. Исходные байты, хеш,
ссылка, основание использования и созданный сигнал сохраняются вместе.
При ошибке не остаётся частично загруженных сведений. Импорт предназначен только
для публичных бизнес-фактов, допустимых для бессрочного хранения: в существующем
хранилище доказательств ещё нет удаления по сроку. Платные лицензионные выгрузки,
личные контакты и приватные документы требуют другого режима хранения.

## Локальный просмотр карточек TenderPlan

Для существующей зашифрованной очереди native TenderPlan доступна отдельная панель
просмотра. По умолчанию она выключена; оператор явно выбирает очередь при запуске:

```powershell
.\python_runtime.bat -B -m lead_factory.cli serve-radar --workspace-db state/radar-research.sqlite3 --actor owner --tenderplan-review-store <existing-native-queue.sqlite3>
```

Сервер не создаёт и не восстанавливает эту очередь. Список содержит только
метаданные и ссылки, связанные с точной зашифрованной карточкой, запуском и
идентификатором хранилища. Открытие одной ссылки расшифровывает только её минимальную
проекцию через Windows DPAPI текущего пользователя. API-ключ источника не читается,
запросов провайдеру нет. Повреждённая или перенесённая очередь, изменённая ссылка
и недоступный ключ приводят к отказу без вывода содержимого и локальных путей.

Действует исходный `expires_at_utc` карточки; просмотр не продлевает срок. Сервер
проверяет его до расшифровки и после итоговой проверки целостности. При наступлении
срока карточка недоступна (HTTP 410), хотя метаданные остаются видимыми. Панель
очищает открытые сведения по сроку, при смене карточки или объекта и уходе со
страницы. Ответы требуют токен локальной сессии и тот же origin, запрещают кеширование.
Сам просмотр не удаляет зашифрованные записи или их копии: отдельные обязательства
по удалению ключей и резервных копий остаются в native retention-процессе.

Числа, даты, регион и статус поставщика показываются исходными строками с пометкой
`UNVERIFIED_PROVIDER_SEMANTICS`; единицы, часовой пояс и значение кодов не установлены.
Карточка не создаёт объект Radar, назначение менеджеру или квалифицированную
возможность. Лицензионные поля не копируются в бессрочные доказательства, задачи
или журнал Radar. Для последующего назначения нужна отдельно проверенная связь
с реальным объектом и ручная квалификация. Просмотр не закрывает source-controller
batch и не меняет его блокировки или разрешения внешних действий.

## Что ещё нужно для запуска продаж

После проверки первого публичного реестра нужно проверить
несколько досье вручную и выдать менеджеру приоритетную очередь. Затем связать
действия менеджера с Bitrix, контактами, документами расчёта и общей блокировкой
контактов. Подтверждение результата должно опираться на реальные записи CRM и
документы, а не только на локальный статус.

Карта всей России, фоновые API-обновления, автоматический анализ документов,
генерация и отправка КП, распределение между сотрудниками с авторизацией и
обучение по результатам продаж в эту поставку не входят. Источники Wave1 по-прежнему
работают на контрольных файлах. Текущая runtime-authority и внешние stop-флаги
не изменены.

## Проверка

```powershell
.\python_runtime.bat -B -m pytest tests/test_lead_factory_radar_workbench.py tests/test_lead_factory_radar_workbench_import.py tests/test_lead_factory_radar_workbench_demo.py tests/test_lead_factory_radar_workbench_server.py tests/test_lead_factory_cli_work_queue.py -q
```

Проверяются сохранение и повтор команды, конфликт версии, права исполнителя,
блокировка после отказа от контакта, атомарный откат, свежесть и разрешения источника,
HTTP-защита от запросов с другого сайта и сохранение маркера демонстрации.
